# M9 上线前检查表

本表供 M9 在目标主机执行；M8 隔离演练不表示这些项已经通过。执行前记录操作人、时间、目标公网 IP、备份目录、目标测试群 ID、回退负责人，不在记录里粘贴凭据。

1. **配置与容量**：核对 `deploy/.env.prod` 权限 600、随机密钥、MySQL 与 OSS 私有权限；`docker compose config --quiet`，仅 80/443 公网映射；数据库 V6，测试数据流程、空载和双 UP 峰值至少余 256 MiB、无持续交换或 OOM。
2. **证书**：确认 80 的 ACME 路径可从公网访问；Certbot staging 与正式 IP 证书分别签发，浏览器验证 IP SAN 与 CA 信任；记录到期时间、续期定时任务退出状态，演练 deploy hook 后证书指纹变化及 HTTPS 仍可访问。
3. **先备份**：备份旧脚本 JSON 状态、队列和路由文件并隔离保存；新库执行 `backup.sh`，复制 SQL、Key 清单和解密必需密钥到主机外；隔离恢复并用真实 OSS 对象清单做 Key 对账。
4. **核对投递影响**：在管理页逐个核对启用 UP、专属路由、运维群、默认群、待发数、首次基线可能重发的存量内容；所有冒烟消息先用专用测试群。历史动态及评论的作废事件不得出现在待发队列。
5. **单发送器切换**：列出旧普通/固定监控的 systemd、cron、容器、tmux/进程；逐一停用并验证无旧进程与无旧飞书消息，再显式启用新 Compose `monitor` profile。记录两次状态快照与切换时间；任何一步不明则不启动新 monitor。
6. **冒烟与回退**：先用测试 UP/群/Bucket 验证扫描、评论、图片、失败重试、心跳和重启续投；正式开放前复核群与 Cookie。回退时先停新 monitor 并确认不再发送，再恢复旧脚本和原状态；记录可能重复发送的区间，已发通知无法撤回。

完整命令、证书参数和备份恢复边界见[部署手册](DEPLOYMENT.md)；上线验收按[OPS-02～05](ACCEPTANCE.md)逐项留证。
