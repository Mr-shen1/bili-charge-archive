## 1. 目标、边界与技术基线

最终交付：管理员可在手机上登录、配置多个 UP 与飞书群、浏览已保存的充电文字/图片动态及评论；Python 按规则持续采集；MySQL 保存内容、进度和待发事件；图片进入私有 OSS；飞书通知可重试；在目标 2 GB 阿里云主机经实际验收后运行。

需求优先级为 **PRD → 其他设计文档 → 现有 Python 脚本**。现有脚本用于参考 B 站解析、评论审计和飞书消息格式，不能照搬其中的文件状态、路由或凭据。原始需求文档、图片和脚本保留；不创建 `AGENTS.md`。不补抓最新 50 条以外的普通历史动态，不迁移旧 JSON 状态与飞书队列。

已确认后端为 Spring Boot 3.5.x、JDK 21、原生 MyBatis，Starter 使用 3.0.x 兼容系列。本计划以 **Maven + Flyway + Vue 3 / TypeScript / Vite** 作为可直接执行的实施默认值；这三项尚未被用户单独确认，若用户另选，应先修改 M0 和相关验证命令。Python、Node、MySQL 镜像及所有依赖的具体版本由 M0 查官方兼容信息后固定，并写入工程文件，禁止在可复现构建中使用 `latest` 标签。

建议目录：`backend/`（Spring、MyBatis、迁移与测试）、`frontend/`（Vue 页面）、`monitor/`（新 Python 监控与测试）、`deploy/`（Compose、Nginx、证书与备份脚本）。这属于工程组织建议，不改变现有资料目录。

## 2. 每个 Goal 的共同执行规则

1. 开始前读本计划、README、相关设计文档和 `docs/IMPLEMENTATION_STATUS.md`（M0 创建）；仅实现本里程碑及其必要依赖。文档冲突先对照 PRD；若会改变用户已确认的行为，记录冲突并询问，不自行改写需求。
2. 每个里程碑交付可运行代码、针对关键风险的测试、运行说明和结果记录。更新状态文件：本阶段修改的文件、验证命令及输出摘要、未通过项、外部联调状态、下一阶段入口。验证失败先修复；不能因文件已生成就标记完成。
3. 使用模拟 B 站响应、测试群和测试 Bucket 完成本地验证。**模拟通过只表示本地通过**；真实 B 站、飞书、OSS、IP HTTPS 和 2 GB 容量分别需要实测，不能用模拟结果代替。缺少凭据或服务器访问时，继续能独立完成的本地工作，并在状态文件中标为“真实联调待完成”。
4. 不从旧脚本或 `feishu_routes.json` 复制 Cookie、Webhook 等实际值到新代码、测试、文档、日志或版本库。测试只用虚构值；真实值由部署环境或管理页注入。不得在前端或公开 API 暴露内部令牌、密钥或完整 Webhook。
5. 每个 Goal 只在其退出条件有实际证据时结束，不自动进入下一阶段。最终“项目完成”还需要 M9 的真实环境验收；任何较早阶段的完成仅表示该阶段通过。

项目已建立本地 Git 仓库。新对话应在同一项目目录工作，并以状态文件传递进度。原脚本与路由文件含实际凭据，须持续排除，不能直接 `git add .`；建立远端仓库和发布不属于 M0 的自动步骤。

## M3. 内容批次事务入库

**实现**

## M4. Python 扫描器与进程生命周期

**实现**

- 新建监控程序，复用原脚本的有效解析/审计思路，但以 Spring 内部 API 代替 JSON 状态和本地飞书队列。管理进程按启用 UP 保证每 UP 一个子进程，停用后在安全点退出，异常后退避重启；Cookie 不进命令行。

## M6. 图片任务与私有 OSS

**实现**

- Spring 后台任务从图片待处理状态读取来源图，校验下载地址、使用必要的 B 站请求头或 Cookie，上传到私有 OSS，记录对象 Key；失败保留文字并退避重试，确定不可用才标记 `UNAVAILABLE`。头像继续使用来源链接。
